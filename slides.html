1

动机与全景

日常使用的 tactic，都是 Lean 程序

simp、omega、ring、linarith、exact? 都不是写死在编译器里的。它们是用 Lean 写的程序，在证明被检查之前运行，任务是造出证明项。

这种“操作 Lean 程序（包括证明）的 Lean 程序”叫元程序。

Mathlib 的 ring 就是一个普通的 .lean 文件，可以直接跳转到定义去读。

今天的目标：写出几个自己的 tactic，并能大致读懂这些源码的结构。

从源码到 kernel

源码文本

tactic 在这一步运行

by ... 里的 tactic 在 elaboration 阶段运行，唯一职责是产出一个 Expr。

kernel 不关心 tactic。tactic 写错了，造出的项会被拒绝。因此元编程不会破坏可靠性。

tactic 证明就是“造项的程序”

example (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
  show_term constructor <;> assumption
-- Try this: exact ⟨hp, hq⟩

show_term 打印 tactic 造出来的项。项（term）就是 Lean 里的表达式，证明也是项：⟨hp, hq⟩ 即 And.intro hp hq，它的类型 p ∧ q 就是要证的命题。

set_option pp.all true in
#check fun (n : Nat) => n + 1

打开 pp.all 能看到所有隐式参数和类型类实例，也就是 elaborator 实际产出的东西。

2

Lean 作为编程语言

定义与求值

def double (n : Nat) : Nat := 2 * n
#eval double 21          -- 42

def sumList : List Nat → Nat
  | []      => 0
  | x :: xs => x + sumList xs

#eval sumList [1, 2, 3]  -- 6

def findFirstEven (xs : List Nat) : Option Nat :=
  xs.find? (fun x => x % 2 == 0)
#eval findFirstEven [1, 3, 4]   -- some 4

#eval 运行并打印结果；#check 只看类型。

Option α 表示可能失败的计算：some x 或 none。元编程里大量 API 返回 Option。

fun x => … 是匿名函数。

== 比较两边的值并返回 Bool

单子：带有环境的计算

单子 M 是一种计算环境。M α 是“在 M 里运行、最后产出 α 的计算”。

IO：读写文件、打印

MetaM：查询类型、构造项

TacticM：读写目标列表

def roll : IO Unit := do
  let n ← IO.rand 1 6
  IO.println s!"掷出 {n}"

IO.rand 1 6 不是一个数，而是“去掷一次骰子”这个计算：它需要访问一些外部环境。← 运行它，取出结果 n。

do 记法

def demo : IO Unit := do
  let xs := [1, 3, 4, 7]
  let mut total := 0
  for x in xs do
    IO.println s!"x = {x}"
    total := total + x
  IO.println s!"total = {total}"
  match findFirstEven xs with
  | some n => IO.println s!"first even: {n}"
  | none   => IO.println "no even number"

#eval demo

IO Unit：一个可以做 IO、最后返回 Unit 的计算。

do 块里可以按顺序写步骤：let mut、for、if、match、return、try … catch。

s!"…{x}…" 是字符串插值。

3

Syntax：代码是数据

Syntax：parser 产出的树

源码 exact ⟨hp, hq⟩ 解析之后：

  • exact
    • "exact"
    • anonymousCtor
      • "⟨"
      • hp
      • ","
      • hq
      • "⟩"

节点只有三种：node 带一个种类名，atom 是关键字和符号，ident 是标识符。

它只记录形状：不知道类型，也不知道 hp 指向哪条假设。

（种类名做了简化。）

Syntax 是普通的数据，可以拆开、匹配、拼出新的。宏就是在做这件事。

Syntax 是数据：可以拼，也可以改

-- 拼：a + b 就是一个 node，三个孩子
def plusStx : Syntax :=
  Syntax.node SourceInfo.none ``«term_+_» #[mkIdent `a, mkAtom "+", mkIdent `b]

-- 改：把 + 节点换成 * 节点
def plusToTimes (stx : Syntax) : Syntax :=
  stx.rewriteBottomUp fun s =>
    match s with
    | Syntax.node info ``«term_+_» #[a, _, b] =>
        Syntax.node info ``«term_*_» #[a, mkAtom "*", b]
    | _ => s

run_meta do
  logInfo m!"{plusStx}"              -- a + b
  logInfo m!"{plusToTimes plusStx}"  -- a * b

run_meta do …：运行一段元程序，logInfo 把结果显示在 infoview。

改的时候完全不关心 a 是什么类型，只是在换树上的节点。to_additive 就是用类似的方法实现的。

4

Expr：项也是数据

Expr：完全显式的项

x + ySyntax
elaborate
@HAdd.hAdd Nat Nat Nat (instHAdd …) x yExpr：名字已解析，隐式参数和实例都写了出来
const全局常量 And、Nat.add
app f a函数应用，一次一个参数
lam / forallEfun，以及 ∀ 和 →
mvar元变量 ?g

没有专门的 ∧、=、+，都是常量的应用：

p ∧ q
= app (app (const And) p) q

证明也是 Expr，比如第 6 页的 And.intro hp hq。pp.all 显示的就是 Expr 的完整样子。

构造 Expr

def onePlusTwo : Expr :=
  mkApp2 (mkConst ``Nat.add) (mkNatLit 1) (mkNatLit 2)

def trueAndFalse : Expr :=
  mkApp2 (mkConst ``And) (mkConst ``True) (mkConst ``False)

run_meta do
  logInfo m!"{onePlusTwo} : {← inferType onePlusTwo}"      -- Nat.add 1 2 : Nat
  logInfo m!"{trueAndFalse} : {← inferType trueAndFalse}"  -- True ∧ False : Prop

mkConst、mkApp2、mkNatLit：就是上一页的 const、app，换了个好写的名字。

m!"…"：可以插入 Expr 的字符串插值。

操作 Expr

-- 读：是不是 p ∧ q 的形状
def andParts? : Expr → Option (Expr × Expr)
  | Expr.app (Expr.app (Expr.const ``And _) p) q => some (p, q)
  | _ => none

-- 改：交换 Nat.add 的两个参数
def swapAdd (e : Expr) : Expr :=
  e.replace fun sub =>
    match sub with
    | Expr.app (Expr.app (Expr.const ``Nat.add _) a) b =>
        some (mkApp2 (mkConst ``Nat.add) b a)
    | _ => none

run_meta do
  match andParts? trueAndFalse with
  | some (p, q) => logInfo m!"左 {p}，右 {q}"  -- 左 True，右 False
  | none        => logInfo "不是合取"
  logInfo m!"{swapAdd onePlusTwo}"   -- Nat.add 2 1
  logInfo m!"{← whnf onePlusTwo}"    -- 3

和 Syntax 一样：match 拆，构造子拼。

Expr.replace：返回 some 就替换这个子项，none 就继续往里找。

Expr 能被归约：whnf 把 1 + 2 归约成 3。

5

元变量与证明目标

证明状态背后是什么

?g
p q : Prop
hp : p
hq : q
⊢ p ∧ q

每个目标是一个元变量 ?g：证明项（一个 Expr）里还没填的洞，也就是上一节的 mvar。它带着：

一个类型：⊢ 后面的 p ∧ q，本身也是 Expr

一个 local context：横线上面的假设

一个赋值：一开始为空。解决目标 = 给这个 mvar 赋一个类型正确的 Expr。

by ... 会推断当前位置所需的类型，并创建一个元变量。

constructor 做了什么

?g
⊢ p ∧ q
?g₁⊢ p
?g₂⊢ q

?g := And.intro ?g₁ ?g₂

tactic 的工作模式：拿到一个洞，要么直接填上，要么填上一个带着更小的洞的项，再更新目标列表。

所有洞都填满后，把赋值代入，就得到完整证明项。

tactic 是改写证明状态的程序

证明状态 = 一个目标列表 [?g₁, ?g₂, …]，每个目标是一个 mvar。

一个 tactic 应当做的事情只有几类：

  • 读：目标的类型和局部上下文（都是 Expr）
  • 造：新的 Expr，里面可以带新的 mvar
  • 写：给目标 mvar 赋值
  • 更新：把目标列表换成剩下的洞

第 8 节写的每一个 tactic，都是这四步的组合。第 6 节讲怎么读写 Expr 和 mvar，第 7 节讲怎么构造 Syntax。

MetaM：读写 Expr 和目标

单子栈

CoreM环境、选项、报错
MetaMmvar、局部上下文、类型推断、unify
TermElabMSyntax → Expr
TacticM目标列表

一层套一层，外层的能力内层都有。

在 TacticM 里可以直接调用任何 MetaM 函数，Lean 自动提升。

对照第 4、5 节：Expr 和 mvar 归 MetaM 管，目标列表归 TacticM 管。

回到第 4 节的例子：哪些需要 MetaM

run_meta do
  logInfo m!"{onePlusTwo}"                      -- 纯数据，不需要单子
  logInfo m!"类型: {← inferType onePlusTwo}"     -- 要查环境：MetaM
  logInfo m!"whnf: {← whnf onePlusTwo}"         -- 要展开定义：MetaM

构造和模式匹配 Expr 是纯函数，第 4 节的 def 都不在单子里。

要知道常量的类型、定义，或者要读写 mvar，就得在 MetaM 里，用 ← 取结果。

识别 Expr 的形状

e.isAppOf ``And          -- Bool
e.isAppOfArity ``And 2   -- Bool
e.getAppFn               -- 头部函数
e.getAppArgs             -- 参数数组
e.and?    -- Option (Expr × Expr)
e.eq?     -- Option (Expr × Expr × Expr)
e.not?    -- Option Expr

let some (p, q) := target.and?
  | throwError "目标不是合取"
-- 这里 p q 可用

这些都是在树上做模式匹配：头部是不是某个 const，参数有几个。

识别是纯语法的。def MyProp := p ∧ q，目标是 MyProp 时 and? 返回 none。

目标里也可能有已赋值未代入的 mvar。

先规范化再识别：goal.getType' 会做 instantiateMVars + whnf。

五个最常用的函数

inferType e求 e 的类型
isDefEq a b定义等价？必要时展开定义；有 mvar 时尝试赋值使两边相等（unify），失败则撤销
whnf e弱头范式：一直归约最外层，直到头部不能再展开
instantiateMVars e把已赋值的 mvar 代入
mkFreshExprMVar ty创建新的洞。

unify：apply 的本质

run_meta do
  let m ← mkFreshExprMVar (mkConst ``Nat)                 -- ?m : Nat
  let lhs := mkApp2 (mkConst ``Nat.add) m (mkNatLit 1)    -- ?m + 1
  let rhs := mkApp2 (mkConst ``Nat.add) (mkNatLit 41) (mkNatLit 1)
  let ok ← isDefEq lhs rhs
  logInfo m!"{ok}, ?m := {← instantiateMVars m}"
  -- true, ?m := 41

apply h：为 h 的每个参数造 mvar，用 isDefEq 把结论和目标unify，没被确定的 mvar 变成新目标。

进入 TacticM：看目标

elab "show_goal" : tactic => do
  let goal ← getMainGoal
  goal.withContext do
    logInfo m!"目标: {← goal.getType}"
    for decl in (← getLCtx) do
      if decl.isImplementationDetail then continue
      logInfo m!"假设 {decl.userName} : {decl.type}"

example (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
  show_goal
  exact ⟨hp, hq⟩

elab "show_goal" : tactic => do …：注册一个新 tactic，后面是一段在 TacticM 里运行的程序。

getMainGoal：取主目标。

withContext：进入目标的局部上下文。

手动填一个洞

elab "prove_true" : tactic => do
  let goal ← getMainGoal
  goal.assign (mkConst ``True.intro)  -- ?g := True.intro
  replaceMainGoal []                  -- 没有新目标

example : True := by prove_true

第 5 节的“写”和“更新”两步。replaceMainGoal gs：把主目标换成列表 gs，空列表表示已完成。

对 ⊢ False 用 prove_true？assign 不检查类型，这一步“成功”了，但最终检查证明项时报错。

7

引用与宏

引用：构造 Syntax 的简写

第 3 节手拼过 Syntax 树。写一个稍大的 tactic 就很啰嗦（示意）：

Syntax.node ``Lean.Parser.Tactic.exact #[
  Syntax.atom "exact",
  Syntax.node ``Lean.Parser.Term.anonymousCtor #[
    Syntax.atom "⟨", Syntax.ident `hp, Syntax.atom ",", Syntax.ident `hq, Syntax.atom "⟩"]]

引用（quotation）让我们直接写出想要的代码，由 parser 代为造出这棵树：

`(tactic| exact ⟨hp, hq⟩)     -- 一棵 Syntax 树，按 tactic 语法解析

引用不执行代码，而是返回代码对应的数据。tactic| 告诉 parser 按哪种语法类别解析，`(…) 不写类别时默认按项（term）解析。

第一个宏 tactic

macro "my_trivial" : tactic =>
  `(tactic| first | rfl | omega | simp)

example : 2 + 2 = 4 := by my_trivial
example (n : Nat) : n + 0 = n := by my_trivial
example (a b : Nat) (h : a < b) : a + 1 ≤ b := by my_trivial
  • macro "my_trivial" : tactic 声明一种新语法，属于 tactic 类别。
  • => 后面是一个 Syntax → MetaM Syntax 的函数：看到 my_trivial 这棵树，就换成右边那棵。
  • simp 放最后，因为它只化简不解决目标也算成功。

反引用 $h：在模板里留洞

macro "apply_close " h:term : tactic =>
  `(tactic| (apply $h <;> assumption))

example (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
  apply_close And.intro

h:term：这个位置接受一个项，绑定到 h 的是它的 Syntax 树，还没有 elaborate。

$h 叫反引用（antiquotation）：把已有的一棵子树插进模板。引用是带洞的树，反引用就是洞的位置。

syntax + macro_rules：引用也能做模式

syntax "easy" : tactic

macro_rules | `(tactic| easy) => `(tactic| rfl)
macro_rules | `(tactic| easy) => `(tactic| assumption)
macro_rules
| `(tactic| easy) => `(tactic| (constructor <;> easy))

example (p q : Prop) (hp : p) (hq : q) :
  p ∧ (q ∧ 3 = 3) := by easy

声明语法和展开规则分开写。| 左边的引用是模式，用来匹配输入的树；右边的引用是输出。

同一个语法可以有多条规则：从最后定义的开始试，失败就回退到更早的。

任何人都能在别的文件里给 easy 加规则。核心里的 trivial 就是这样扩展的。

宏的边界，以及从 Syntax 到 Expr

elab "#expr " t:term : command =>
  Command.liftTermElabM do
    let e ← instantiateMVars
      (← Term.elabTermAndSynthesize t none)
    logInfo m!"{e}\n{repr e}"

#expr fun (x : Nat) => x
#expr (2 + 3 : Nat)    -- 看看 HAdd.hAdd 和实例

宏只做 Syntax → Syntax。它看不见目标是什么类型，也没法根据假设的形状做判断。

elab 可以拿到 Syntax 之后亲手调用 elaborator，得到 Expr。左边就是第 4 节那条 elaborate 箭头的代码版。

Expr 也有带类型检查的引用写法，在 Mathlib 依赖的 Qq 库里，今天不讲。

8

动手写 tactic

my_assumption

elab "my_assumption" : tactic => do
  let goal ← getMainGoal
  goal.withContext do
    let target ← goal.getType
    for decl in (← getLCtx) do
      if decl.isImplementationDetail then continue
      if (← isDefEq decl.type target) then
        goal.assign decl.toExpr
        replaceMainGoal []
        return
    throwError "my_assumption: 没有类型为 {target} 的假设"

example (p q : Prop) (hp : p) (hq : q) : q := by
  my_assumption

先用 isDefEq 检查，再赋值，所以不会造出错误的证明。

decl.toExpr：局部声明对应的 fvar。

isDefEq 比 == 强：会展开定义。但它不懂对称性：a = b 与 b = a 并非按定义相等，因此h : a = b 不能解决 b = a。

split_and

elab "split_and" : tactic => do
  let goal ← getMainGoal
  goal.withContext do
    let target ← goal.getType'
    let some (p, q) := target.and?
      | throwError "split_and: 目标不是合取: {target}"
    let gp ← mkFreshExprSyntheticOpaqueMVar p `left     -- ?left  : p
    let gq ← mkFreshExprSyntheticOpaqueMVar q `right    -- ?right : q
    goal.assign (mkApp4 (mkConst ``And.intro) p q gp gq)
    replaceMainGoal [gp.mvarId!, gq.mvarId!]

example (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
  split_and
  · my_assumption
  · my_assumption

?g := And.intro ?left ?right。新 mvar 在 withContext 内创建，继承原目标的假设。

my_intro：使用现有 API

elab "my_intro " x:ident : tactic => do
  let goal ← getMainGoal
  let (_, newGoal) ← goal.intro x.getId
  replaceMainGoal [newGoal]

example (p q : Prop) : p → q → p := by
  my_intro hp
  my_intro hq
  exact hp

MVarId.intro 内部：加一个 fvar x : α，造新目标 ?g' : β x，令 ?g := fun x => ?g'。

MVarId 上现成的：intro、apply、assumption、cases、induction、rewrite、exfalso、clear……

evalTactic：组合已有 tactic

elab "auto_and" : tactic => do
  evalTactic (← `(tactic| repeat' split_and))
  evalTactic (← `(tactic| all_goals first | my_assumption | rfl | omega))

example (p q : Prop) (hp : p) (hq : q) (n : Nat) (h : n > 3) :
    (p ∧ 1 + 1 = 2) ∧ (q ∧ n ≥ 2) := by
  auto_and

构造 tactic 语法，再运行它。repeat' 对所有子目标反复应用，all_goals 对每个剩余目标运行。

smart：看了目标再决定

syntax "smart" : tactic

elab_rules : tactic | `(tactic| smart) => do
  let goal ← getMainGoal
  let target ← goal.withContext goal.getType'
  if target.isAppOf ``And then
    evalTactic (← `(tactic| split_and <;> smart))
  else if target.isAppOf ``Eq then
    evalTactic (← `(tactic| first | rfl | omega | simp))
  else
    evalTactic (← `(tactic| my_assumption))

example (p : Prop) (hp : p) (n : Nat) :
    p ∧ (n + 0 = n ∧ 2 * 3 = 6) := by
  smart

要在实现里引用 smart 自己，得先用 syntax 声明语法，再用 elab_rules 写实现，和第 7 节的 macro_rules 同理。直接写 elab "smart" 时，函数体里的 smart 还没注册，解析失败。

宏做不到这件事，因为宏看不见目标。这就是从 macro 走到 elab 换来的能力。
